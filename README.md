## 这是什么

我在学校时做了个教务政策问答（见另一个仓库），发现一个问题：

**「附近有什么好吃的」这类问题，高德能给你 600 家店，但你不知道选哪家。**

所以我做了这个：不是「搜给你看」，是「替你做决定」。

同一个问题，它会考虑：

- **你现在几点**（晚上 8 点不推景区，推夜市和 KTV）
- **你能走多远**（吃饭 1.5km，逛景点 8km）
- **你的预算**（人均 150 时，便宜小吃会排后面）
- **交通方式**（步行 37 分钟 / 骑行 12 / 公交 20 / 驾车 12）

## 和「高德官方 MCP」的区别

高德已经有官方 MCP Server，做的是「把周边搜索暴露给模型」。

我做的不是封装 API，是**上面的那层决策**：

| | 高德官方 MCP | 本项目 |
|---|---|---|
| 输入 | 「附近有什么好吃的」 | 「我和女朋友过纪念日，人均 150，想安静点」 |
| 流程 | 调一次周边搜索 | **拆意图 → 分类型搜 → 按预算/距离/时间加权 → 算路线 → Critic 复核** |
| 工具 | 1 个 | **5 个**（地理编码 / 周边 / 全城 / 路线 / 天气） |
| 输出 | POI 列表 | **能直接执行的计划 + 每步理由** |

## 设计要点

### ① 意图分四类，半径跟着变

| 意图 | 触发词 | 半径 | 搜索方式 |
|---|---|---|---|
| `eat` | 吃/饭/餐厅 | 1.5km → 3km | 周边搜索 |
| `drink` | 喝/奶茶/咖啡 | 1km → 2km | 周边搜索（只留饮品） |
| `sight` | 景点/古迹 | 8km → 15km | **按行政区搜索** |
| `play` | 能去哪玩 | 3km → 8km | 周边搜索（景点+娱乐+商圈） |
| `travel` | XX市有什么 | 全城 | 全城关键字搜索 |

**为什么 `play` 和 `sight` 要分开**：

```
「附近有啥景点」→ 明确要景点，商场降权
「附近能去哪玩」→ 开放式，奥莱、华清电竞、夜市都算
```

### ② 评分排序，不叫「质量排序」

```python
score = 0.5 × 归一化评分
      + 0.3 × 预算匹配度（人均是否接近用户预算）
      + 0.2 × 类型匹配
      + 地标加分（钟楼/老街/不夜城 +0.15）
      - 商场降权（奥莱/购物中心 -0.30，仅 sight 场景）
      + 时间加权（晚上不推白天景点）
      - 距离惩罚（eat 0.30 / sight 0.10 / 约会 0.05）
```

**为什么特意说「不叫质量排序」**：

高德评分是用户打的，有刷分、有样本偏差。**评分高 ≠ 质量好**，只是「评分高的排前面」。

### ③ Planner-Critic 双阶段

```
Planner: 解析意图 → 搜索 → 排序 → 算路 → 组织答案
Critic:  时间够吗？距离合理吗？预算超了吗？
         不通过 → 打回（最多 2 次）
```

**Critic 不是摆设**，实测能拦住：

```
用户：两小时能去哪玩
Planner：5 个景点，总耗时 543 分钟
Critic：「你只有 120 分钟，每个地方 90 分钟 + 步行 19 分钟，最多去 1 个」
→ 重排成 1 个，通过
```

### ④ 半径自适应 + 结果兜底

```
搜到 >= 3 条  → 直接用
搜到 < 3 条   → 半径 × 1.5 再搜（最多 2 次）
结果 < 5 个   → 放宽时间限制再排（并标注「部分地点可能已关门」）
```

### ⑤ 事实准确率 100%

所有 POI 都来自高德，**不可能编造不存在的地方**。这是 LLM 自己生成做不到的。

## 评测

20 条手工标注（`data/eval_set.jsonl`）：

**两份评测集，如实报告**：

| 数据集 | 说明 | 结果 |
|---|---|---|
| **调参集**（20 条） | 边开发边设计的，等于用测试集调参 | 意图 100% / 结果 100% / 事实 100% |
| **留出集**（10 条） | 最后盲写、只跑一次、没调过 | **意图 90% / 结果 100%** |

留出集唯一失败的是「带外地朋友玩，有啥陕北特色的」——
系统在附近给了博物馆和遗址（内容合理），但判成「附近玩」而不是「全区域搜陕北」。
**这是意图粒度上的判断差异，也是「附近」和「全城」边界模糊的真实体现。**

真实准确率看留出集：**90%**。

复现：

```powershell
python tests/eval.py
```

## 快速开始

### 1. 准备

```powershell
pip install fastapi uvicorn openai mcp langgraph
```

### 2. 配置

复制 `.env.example` 为 `.env`，填三个 key：

```ini
AMAP_KEY=<高德 Web 服务 key>
AMAP_JS_KEY=<高德 Web 端 JS API key>
DEEPSEEK_API_KEY=<DeepSeek key>
```

**两个高德 key 不一样**：
- `AMAP_KEY`：服务平台选「Web 服务」，服务端调用
- `AMAP_JS_KEY`：服务平台选「Web 端(JS API)」，前端地图用

### 3. 跑

```powershell
python server.py
```

打开 <http://127.0.0.1:8000>

## 已知限制

| 限制 | 说明 |
|---|---|
| **高德 QPS ≈ 3 次/秒** | 每次调用间隔 1 秒，单次问答 5–10 秒 |
| **IP 定位本地不可用** | 127.0.0.1 没有公网 IP，部署到服务器才准 |
| **交通时间除步行外都是估算** | 骑行/公交/驾车按平均速度推算，界面已标注 |
| **夜间推荐靠类型粗判** | 高德 POI 的 `open_time` 覆盖率低，很多店没有 |
| **不支持饭点排队 / 实时营业状态** | 高德不提供这类数据 |
| **「地方特色」靠关键词匹配** | 用「陕北/窑洞/非遗/老街」这类词加权，不是真正的文化理解 |
| **抽象需求处理不了** | 「有仪式感」「适合纪念日」这类，只能反问或给通用推荐 |

## 部署

线上环境：

```
腾讯云轻量 2核2G · Ubuntu 22.04
systemd 托管 city-agent.service（只监听 127.0.0.1:8000）
nginx 反向代理 + Let's Encrypt 证书（8443 端口）
```

`deploy/` 目录下有完整的部署脚本：

| 脚本 | 作用 |
|---|---|
| `remote.py` | SSH 执行命令的小工具 |
| `upload.py` | tar 打包上传（**不用 zip**，Windows 的 zip 会扁平化目录 + 用反斜杠） |
| `setup_env.py` | 建 venv + 装依赖 + 写 .env |
| `setup_systemd.py` | 配 systemd 服务 |
| `setup_nginx.py` | 配 nginx 反向代理 |
| `get_cert.py` | 申请 Let's Encrypt 证书（HTTP-01） |
| `switch_cert.py` | 换成真证书配置 |

**踩过的坑**（都写在注释里了）：
- `Compress-Archive` 传多文件会扁平化目录 → 用 `tar`
- Windows zip 用反斜杠 → Linux 解压成了文件名
- cloudflared 在腾讯云上启动即 SEGV（CPU/glibc 都没问题，判断是安全策略）
